PAWTHENTIC
01

Blockchain / Full stack

Adopt Me

A pet adoption platform where ownership history is verified on-chain, so buyers can trust where an animal actually came from.

  • React
  • Solidity
  • Node.js
  • MongoDB

What I built

  • A React frontend for browsing listings and managing adoption requests
  • Solidity smart contracts that mint and transfer an NFT as proof of ownership
  • A Node.js/MongoDB backend for listings, user accounts, and adoption records
  • A verification flow that checks on-chain ownership before a transfer completes
GitHub ↗
Why blockchain, not just a database

Pet adoption scams usually come down to one thing: no one can verify who actually owned an animal before. Putting ownership transfer on-chain makes that history checkable by anyone, instead of relying on a listing site's word for it.

AI RESUME MATCHER
02

Applied AI

AI Resume Matcher

Helps candidates see how well their resume actually matches a target role, using the Gemini API instead of simple keyword counting.

  • React
  • Express
  • Gemini API

What I built

  • A React interface for pasting a resume and job description side by side
  • An Express API layer that structures the prompt and calls the Gemini API
  • A results view that surfaces where the resume aligns and where it falls short
GitHub ↗
The actual problem it solves

Most resume checkers just count overlapping keywords. This sends both documents to an LLM so the feedback is about substance — matching experience, not matching words.

FITQUEST
03

Frontend / Product

FitQuest

A gamified fitness app that turns workouts into quests and levels, built to make consistency feel less like a chore.

  • React
  • Firebase

What I built

  • A quest system that converts workouts into completable challenges with progress tracking
  • Firebase auth and Firestore for user profiles, streaks, and quest state
  • A responsive interface designed around quick daily check-ins
GitHub ↗
The design bet

Fitness apps fail when logging a workout feels like data entry. Framing it as quests and levels was a deliberate attempt to make the habit-forming part feel like the point, not the tax.

07 / Approach

How I think about a problem

The process I default to, whether it's a contest problem or a product feature.

  1. 01

    Understand

    Figure out the actual problem before touching the actual code.

  2. 02

    Break down

    Split it into pieces small enough to reason about individually.

  3. 03

    Build

    Get to a working version — not a perfect one.

  4. 04

    Improve

    Test it, find where it breaks, and fix that.

  5. 05

    Ship

    Make it usable by someone who isn't me.
